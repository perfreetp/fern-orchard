# 凌霄 · 台风路径与风圈联动观察器

一个用 Babylon.js 构建的三维地球台风观察器。拖动台风中心沿路径移动，四象限风圈半径随强度实时缩放，路径随拖动延伸并让已走过的一段变暗；点击路径或时间轴跳到任意时次，侧栏同步该时刻各象限的风圈数值。

**打开方式：** 直接双击 `index.html`（无需构建、无需服务器）。

---

## 它演示了什么

内侧 `十级 / 十二级` 风圈嵌在 `七级风圈` 里，三个风圈都是**四象限不对称**的 —— 东北、东南两个象限（移动方向右前方）明显大于西南、西北。这来自真实台风报文里 `R34 / R50 / R64` 的分象限发布方式。

预置个例「凌霄」是一条**东海近海增强型**路径：从菲律宾以东生成，西北行穿过琉球群岛后转向北，在浙江外海达到 65 m/s 的强度峰值，随后登陆并迅速减弱。

数据里刻意埋了一个教学时刻：**08-15 20:00（第 96 小时）**。此前七级风圈一直够不到海岸线；随着风暴逼近陆架，风圈在 92→96 小时之间从 150 km 猛增到 446 km，同时海岸线暴露长度从 0 跳到 1400+ km。把中心拖到这个点，就能看到风圈骤然扩张、把浙闽海岸整段吞进去的那一帧，沿海岸线会亮成琥珀色。

> 这是**合成教学个例**，轨迹与强度参照 2019 利奇马、2006 桑美一类东海近海增强台风标定，不是真实观测。

## 操作

| 操作 | 效果 |
| --- | --- |
| 拖动风圈中的准星标记 | 沿路径移动台风，风圈连续缩放 |
| 点击路径上任意点 | 跳到该时刻 |
| 点击/拖动时间轴 | 任意跳转；时间轴下方曲线是风速与雨强的时程 |
| 空格 / 方向键 | 播放暂停 / 前一小时、后一小时 |
| 空白处拖动、滚轮 | 旋转、缩放地球 |
| `R` | 重置视角 |
| `?` | 操作说明 |

## 实现要点

**风圈几何** —— 每帧按方位角求半径：象限内取该象限的定值，边界处 7° 窄带做平滑过渡。这样轮廓既保持四个扇面的棱角，又不会在象限交界处撕裂。三个风圈按 大→小 的顺序绘制，内层才能压住外层的半透明底色（否则三层叠加会平均成灰色）。

**强度曲线** —— 用 Fritsch–Carlson 单调三次插值（`js/geo.js` 的 `Monotone`）在逐小时数据之间取任意时刻，保证风圈半径不会在控制点之间过冲出现鬼影峰。

**路径明暗** —— 路径是一条贴着球面的管状网格，着色器按 `uNow` 把顶点分成已走/未走两段：已走过的一段随时间"变老"、亮度衰减成暗青色，刚走过的一段保持亮青，未走的只留流动的虚线引导。拖动时不需要重建网格，只更新一个 uniform。

**降水粒子** —— 4200 条雨丝全部在顶点着色器里做轨道动画：按方位角查四象限半径得到落点，绕中心缓慢旋转并叠加逐粒子的横向摆动，所以雨幕会跟着风圈一起变形，密度由该时刻的雨强决定。

**海岸线** —— 沿岸线每 1° 建一次经纬度网格桶，逐帧只遍历风暴附近约 17×17 个桶，再用平面近似（北/东分量直接和象限半径比大小）判断是否在风圈内，完全不调三角函数。整段海岸带约有 2700 个顶点被点亮。

## 文件

```
index.html              页面骨架与 HUD
css/app.css             全部样式
js/geo.js               球面几何、单调插值
js/globe.js             Babylon 场景、地球/大气/星空着色器
js/storm.js             台风全部图形：风圈、路径、海岸、雨、云
js/timeline.js          时间轴与强度时程曲线
js/app.js               场景 ⇄ HUD ⇄ 时间轴 ⇄ 指针 的接线
data/*.data.js          生成好的路径与海岸线数据
assets/                 贴图（vendor/ 里是 Babylon 9.38.0）
tools/                  数据与贴图生成脚本 + 测试
```

`tools/` 下的脚本都是确定性的，重新运行结果一致：

```
python -I tools/gen_globe.py     # 地球底图与海陆遮罩
python -I tools/gen_typhoon.py   # 路径、强度、四象限风圈、海岸线
python -I tools/gen_fx.py        # 云系与星空贴图
```

`tools/interact.js`（Playwright）覆盖拖动、路径点击、播放、键盘、响应式布局与每帧 CPU 预算，共 21 项检查。

## 性能

每帧 CPU 侧（`setTime`）已压到约 2–3 ms，主要开销是风圈顶点上传；相机移动时风圈和云顶会比对签名，没有变化就整段跳过。画面在软件光栅化（SwiftShader）下也能跑，真实 GPU 上余量充足。帧率掉到 34 fps 以下时引擎会自动降低渲染分辨率。
